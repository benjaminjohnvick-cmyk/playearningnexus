2
Deploy (web) One command: deploy → turn on → pre-warm → smoke
▶

Save your .env to backend/.env first. Then one-time install the Railway CLI and log in:

npm i -g @railway/cli && railway login

Then the one-command web launch — it deploys, verifies every feature is ON, fills the catalog with content, and smoke-tests:

bash deploy-kit/web-launch.sh
No terminal? Use the Deploy on Railway button in the repo README: add a Postgres database, set Root Directory = backend, paste your .env values. Same result.
3
Go-live check Everything ON + content live + GO/NO-GO
▶

web-launch.sh already runs this. To run it on its own against your live URL:

BACKEND_URL=<your-url> ADMIN_EMAIL=<you> ADMIN_PASSWORD=<pw> node deploy-kit/go-live.mjs

It prints GO when the app is up, every flag is ON, and the store is already populated — or the exact items to fix.

4
Mobile signing One command → keystore + paste-ready CI secrets
▶
bash deploy-kit/mobile/setup-signing.sh

It generates the Android keystore and writes ci-secrets.local.txt. Paste each line into GitHub → Settings → Secrets and variables → Actions. The secret names it fills / asks for:

ANDROID_KEYSTORE_BASE64 ANDROID_KEYSTORE_PASSWORD ANDROID_KEY_ALIAS ANDROID_KEY_PASSWORD PLAY_SERVICE_ACCOUNT_JSON (from Play Console → API access) APPSTORE_API_KEY_ID APPSTORE_API_ISSUER_ID APPSTORE_API_KEY_P8 (contents of the .p8 from App Store Connect)
